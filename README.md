# ponoc

> **Private repository.** Proprietary and confidential. Not open source: don't share, publish or copy this code outside the team.

Facts or cap, called live. ponoc listens to you speak, picks out the claims that can be checked, verifies each one against the web, and rules it true or false on a card.

## How it works

One Node process (`server.ts`) serves two things:

- **The Next.js app**: the landing page, `/login`, the deck at `/app`, and the auth API at `/api/auth/*`.
- **A WebSocket gateway at `/ws`**: the browser streams microphone audio in, and verdicts stream back out.

A live session runs this pipeline:

```
mic → 16 kHz PCM → /ws → Deepgram (speech-to-text)
    → Segmenter (finished sentences)
    → triage model (is there a checkable claim?)
    → ClaimQueue (dedupe, prioritise, max 5 at once)
    → verify model + web search (true / false + evidence)
    → card on the deck
```

Sign-in uses [Better Auth](https://better-auth.com) with Google and email magic links. Users, sign-in sessions and per-session usage live in Postgres.

### Code layout

| Path | What lives there |
|---|---|
| `server.ts` | Entry point: HTTP server, Next.js, the `/ws` gateway, graceful shutdown |
| `src/app/` | Next.js routes (pages and the auth API) |
| `src/components/` | UI, grouped by feature: `card`, `credits`, `deck`, `landing`, `login`, `settings` |
| `src/client/` | Browser-only logic: the live-session hook, microphone capture, auth client |
| `src/server/` | Node-only logic: auth, database, gateway, usage and credits, the session pipeline. Never imports Next or React |
| `src/shared/` | Code both sides use: the WebSocket message contract, credit packs |
| `src/server/db/` | Database schema ([Drizzle](https://orm.drizzle.team)): one file per table, plus `index.ts`, which exports them all and the database connection; `migrations/` is generated by Drizzle |

## Running locally

Requires Node 22+ and a Postgres database (the project uses [Neon](https://neon.tech)). Ask for the shared development values, or create your own.

```bash
cp .env.example .env    # then fill it in
npm install
npm run db:migrate      # creates or updates the tables
npm run dev             # http://localhost:3000
```

Without `RESEND_API_KEY`, magic links are printed to the server log instead of emailed.

| Script | Does |
|---|---|
| `npm run dev` | Runs the server with hot reload |
| `npm run build` | Builds the Next.js app |
| `npm start` | Runs the production server |
| `npm run db:generate` | Creates a migration after you change a schema file in `src/server/db/` |
| `npm run db:migrate` | Applies pending migrations to `DATABASE_URL`. Never runs automatically: run it yourself before deploying code that needs it |
| `npm test` | Unit tests (vitest) |
| `npm run typecheck` / `npm run lint` | Type and lint checks |

## Deploying

The app runs on [Railway](https://railway.com), built from the `Dockerfile`. Every push to `main` deploys.

| Railway setting | Value |
|---|---|
| Builder | Dockerfile |
| Build / start command | Empty. The Dockerfile handles both |
| Port | `3000` |
| Healthcheck path | `/` |
| Draining time | `30` seconds. Live sessions get up to 20 seconds to finish verifying and save usage |
| Serverless | Off. The app holds live WebSockets and must stay awake |

- Set every variable from [`.env.example`](.env.example) on the service. Production also needs `RESEND_API_KEY` and `EMAIL_FROM`.
- `SITE_URL` is baked into static pages at build time and read at runtime by the WebSocket origin check, so it must be the public URL.
- Migrations don't run on deploy. Before pushing code that needs one, run `npm run db:migrate` with `DATABASE_URL` set to the production database.

## How usage is priced

Every live session is metered, and one row is written to `live_session` per session. The meter counts four things, because these are what the providers bill for:

| What | Billed by | Env variable | Current value |
|---|---|---|---|
| Triage input / output tokens | OpenAI | `TRIAGE_INPUT_USD_PER_M` / `TRIAGE_OUTPUT_USD_PER_M` | $0.20 / $1.25 per 1M (gpt-5.4-nano) |
| Verify input / output tokens | OpenAI | `VERIFY_INPUT_USD_PER_M` / `VERIFY_OUTPUT_USD_PER_M` | $0.75 / $4.50 per 1M (gpt-5.4-mini) |
| Web searches | OpenAI | `WEB_SEARCH_USD` | $0.01 per search |
| Audio | Deepgram | `DEEPGRAM_USD_PER_MIN` | $0.0077 per minute (Nova-3 streaming list price) |

Values as of September 2026. Web searches are counted separately because OpenAI charges a fee per search on top of tokens. The pages a search reads are billed as input tokens.

### The formula

```
cost    = input tokens × input price + output tokens × output price   (triage and verify each at their own price)
        + web searches × $0.01
        + audio minutes × $0.0077

credits = cost × MARKUP ÷ CREDIT_USD
```

- **`MARKUP`** (currently `2`) is the profit multiplier. Users pay 2× what the usage costs.
- **`CREDIT_USD`** (`0.20`) is what one credit is worth at retail, so **$5 buys 25 credits**.

### Worked example: one busy minute

Illustrative numbers for a minute of speech that produces 8 utterances and 2 checkable claims:

| Item | Amount | Cost |
|---|---|---|
| Audio | 1 minute | $0.00770 |
| Triage input (nano) | 8 × 400 = 3,200 tokens | $0.00064 |
| Triage output (nano) | 8 × 60 = 480 tokens | $0.00060 |
| Verify input (mini) | 2 × 6,000 = 12,000 tokens | $0.00900 |
| Verify output (mini) | 2 × 300 = 600 tokens | $0.00270 |
| Web searches | 2 | $0.02000 |
| **Cost to ponoc** | | **$0.04064** |
| Charged (× 2 markup) | | $0.08128 |
| **Credits** (÷ $0.20) | | **≈ 0.41 credits** |

These token counts are illustrative, not measured. Real cost per minute swings widely with how many checkable claims are said, so the product never shows minute estimates. Measure real rates from `live_session` instead.

### Balance, trial and packs

- Every new account gets **5 free credits** ($1 of retail usage), granted when the account is created.
- A user's balance is `user.credits`, in plain credits. Each session's spending is deducted from it as the session is saved, and recorded in `live_session.credits_used`. To change someone's balance, edit `user.credits` directly.
- A session can't start at zero, and stops when the balance runs out mid-session (close code `4402`). Claims already being checked still finish, so a balance can end slightly below zero.
- Checkout offers three packs, defined in [`src/shared/credits.ts`](src/shared/credits.ts): $2 → 10 credits, $10 → 55 (+10% bonus), $20 → 120 (+20% bonus), plus a custom amount (whole dollars, $2 to $500, at the base rate of 5 credits per dollar, no bonus). The checkout UI ends at "Continue to payment"; payment processing is handled separately.

### Working on payments

Payment processing is built separately. The UI side stops at checkout:

- [`CheckoutDialog`](src/components/credits/CheckoutDialog.tsx) takes an `onContinue(selection)` prop that is not wired up yet. `selection` is `{ packId, usd, credits }`, where `packId` is a pack id or `"custom"`. It's rendered in [`Deck`](src/components/deck/Deck.tsx).
- Packs live in [`src/shared/credits.ts`](src/shared/credits.ts).
- A purchase adds to `user.credits` ([schema](src/server/db/user.ts)) and should log a `credits_topped_up` notification (see [`notify`](src/server/notify.ts)).
- Purchases are non-refundable except where the law requires otherwise, and purchased credits never expire (see the Terms at `/legal#terms`).

### Storage

Money is stored as exact decimals with six places (`numeric(14, 6)`: `user.credits`, `live_session.cost_usd`, `live_session.credits_used`), so it reads plainly and never drifts the way floating-point numbers do. In code, amounts are handled as whole millionths ("micros") and balances are changed in SQL, so the arithmetic stays exact. Both cost and credits are stored, so changing `MARKUP` later doesn't rewrite what past sessions were charged.

### Changing the numbers

- **Switching a model, or a provider changes its price:** edit `.env`. A model and its prices sit side by side, so change them together. All price variables are required; the server refuses to start if one is missing or isn't a number.
- **Changing what users pay:** edit `MARKUP` or `CREDIT_USD` in [`src/server/usage/pricing.ts`](src/server/usage/pricing.ts). These are business rules, so they live in code where every change is reviewed and recorded in git history.

### Useful queries

```sql
-- Overall usage for one user
SELECT count(*) AS sessions, sum(audio_seconds) / 60.0 AS minutes,
       sum(input_tokens) AS input_tokens, sum(output_tokens) AS output_tokens,
       sum(claims_true) AS true_verdicts, sum(claims_false) AS false_verdicts,
       sum(cost_usd) AS cost_usd, sum(credits_used) AS credits
FROM live_session WHERE user_id = $1;

-- The same, per week
SELECT date_trunc('week', started_at) AS week, count(*) AS sessions,
       sum(credits_used) AS credits
FROM live_session WHERE user_id = $1
GROUP BY week ORDER BY week;

-- Set a user's balance
UPDATE "user" SET credits = 0.1 WHERE email = 'someone@example.com';

-- Recent account activity (sign-ups, sign-ins, credits, sessions)
SELECT created_at, email, type, message FROM notification ORDER BY created_at DESC LIMIT 50;
```
